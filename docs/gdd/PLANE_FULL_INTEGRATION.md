Приоритет:
1. Новые решения пользователя (§1 этого документа).
2. CONFIRMED из спеки.
3. ENGINEERING.
4. TEMPORARY.

Если новое решение противоречит спеке, действует новое. Противоречия разобраны в §1.2 — не решай их заново самостоятельно.

Статусы те же, что в спеке:
- **CONFIRMED** — решение пользователя;
- **ENGINEERING** — предложенная инженерная реализация;

Не выдавай TEMPORARY за характеристики реального самолёта. Не пиши «работает», пока нет доказательства (спека §12.8).

### 1.2 Как это сочетается со спекой

- **Реализм полёта и простота процедур (INPUT-01).** Реализм касается физики и показаний, а не длины процедур. Запуск остаётся коротким (§5.4). Шаг винта, смесь и закрылки не обязательны: рычаги работают, но у игрока есть разумные значения по умолчанию.
- **Кнопки дверей и ручные двери (SEAT-02, DOOR-01).**
  - Ручные ручки дверей кабины изнутри и снаружи остаются. Кнопки в кабине добавляются.
  - Нужны ли ручки при наличии кнопок — **OPEN**. До ответа работают оба способа.
- **Ключ.** Ключ — это центральный замок самолёта (§4.3). Кнопки изнутри работают всегда, ключ нужен только снаружи.
  - Ключ зажигания — **OPEN**. По умолчанию его нет, двигатель запускается без ключа.
- **Стиль Half-Life и переноска (GRAB-01).**
  - Движение, ощущение управления и «использовать» — как в Half-Life.
  - Переноска предметов — строго по GRAB-01: захват в точке, ограниченная сила, совместная переноска. Не удерживать предмет за центр перед камерой, как в HL2.
- **Раскладка клавиш.** На земле `E` — «использовать» (HL). В кресле `Q/E` — рысканье (спека INPUT-01). Поэтому в кресле действие «использовать» и выход переносятся на другую клавишу (§3.5). Раскладка настраиваемая (O-01).

## 3. Контроллер персонажа в стиле Half-Life

### 3.1 Архитектура — ENGINEERING

- C++-наследник `ACharacter` и собственный наследник `UCharacterMovementComponent`.
- Формулы ускорения и трения заменить на модель Source/GoldSrc: переопределить расчёт скорости на земле и в воздухе.
- Сетевое предсказание и коррекцию CMC сохранить: saved moves, серверная авторитетность.
- Своё сетевое движение с нуля не писать.

### 3.2 Модель движения — формулы CONFIRMED по стилю, значения TEMPORARY

- Желаемое направление `wishdir` и скорость `wishspeed` задаются вводом.
- Трение на земле:

  ```
  speed = |v|
  drop = max(speed, stopspeed) * friction * dt
  v *= max(speed - drop, 0) / speed
  ```

- Ускорение на земле:

  ```
  add = wishspeed - dot(v, wishdir)
  если add > 0: v += wishdir * min(accel * wishspeed * dt, add)
  ```

- В воздухе то же ускорение, но `wishspeed` ограничен `air_wishspeed_cap`, а `accel = air_accel`. Это даёт управляемый стрейф в воздухе, как в HL.
- Разгон распрыжкой: по умолчанию ограничен потолком горизонтальной скорости `bhop_cap`. Параметр настраиваемый.

| Параметр | TEMPORARY значение (метрические эквиваленты значений HL2) |
|---|---|
| Ходьба / бег / спринт | 2.9 / 3.6 / 6.1 м/с |
| friction / stopspeed | 4.0 / 1.9 м/с |
| accel / air_accel | 10 / 10 (1/с) |
| air_wishspeed_cap | 0.57 м/с |
| Гравитация | 9.81 м/с². Гравитацию HL (≈15 м/с²) не используем: в игре физический груз |
| Прыжок | высота 0.5 м |
| Присед | высота капсулы 0.9 м, прыжок с приседом прибавляет 0.35 м |
| Ступенька | 0.35 м |
| Капсула | высота 1.80 м, радиус 0.34 м, глаза на 1.65 м |
| bhop_cap | 1.1 × скорость бега |

### 3.3 Камера и ощущения

- Мышь 1:1 без ускорения, FOV 90° (настраиваемый).
- Лёгкое покачивание при ходьбе (отключаемое) и просадка камеры при приземлении.
- Шаги по Physical Material: снег, металл пола самолёта, бетон.
- Приземление с высоты — звук и толчок камеры. Урон не утверждён: не добавлять.

### 3.4 «Использовать» — CONFIRMED по стилю

- Трасса из камеры, дальность 2.0 м (TEMPORARY), канал Interact. Дальше маршрут взаимодействия по спеке: цель → серверная проверка → изменение состояния.
- Подсказка при наведении: название, состояние, действие (INPUT-02). Подписи брать из `label` в `interaction_volumes.json`.
- Удержание «использовать» на физическом предмете запускает захват по GRAB-01, в точке попадания трассы.

### 3.5 Кресло, курсор, выход

- **Посадка.**
  - «Использовать» на кресле → мгновенная посадка (SEAT-02). Точка таза — `Socket_Seat_P` / `Socket_Seat_C`, камера — `Socket_PilotEye` / `Socket_CopilotEye`.
  - Голову можно поворачивать: рыск ±135°, тангаж от −70° до +80° (TEMPORARY).
  - Зон курсора для кресел в `interaction_volumes.json` нет. Создать боксы 40 × 40 × 40 см на сокетах кресел.
- **Курсор.** Свободный курсор в кресле — отдельный режим ввода (INPUT-02): клик по элементу из `interaction_volumes.json`. Клавиши полёта при этом активны.
- **Выход.**
  - TEMPORARY-раскладка: в кресле «использовать» — `F`, выход — удержание `F` 0.4 с.
  - Точка выхода — `Socket_Exit_L` / `Socket_Exit_R` у двери своего борта, с проверкой капсулы.
  - Если дверь своего борта закрыта, выход запрещён с подсказкой. Открыть её можно кнопкой или ручкой. Сквозь закрытую дверь не выходим.
- **Руки** (VIEW-01): левая на `Socket_Hand_Yoke_L`, правая на `Socket_Hand_Throttle`, пока газ меняется. Иначе правая на `Socket_Hand_Yoke_R`. Ноги — `Socket_Foot_L/R`. Это IK, отдельные анимации переключателей не нужны.

## 4. Самолёт: сборка и взаимодействие

### 4.1 Сборка актора — ENGINEERING

- Импорт: `ue_import_utility_plane.py`. Результат проверить в P00.
- Корень Pawn/Actor — `SK_UtilityPlane`. Physics Asset: у кости `Body` набор боксов и выпуклых оболочек.
  - Пол, борта, крыша, перегородки, крыло, оперение, капот.
  - Грузовой отсек и все проёмы остаются пустыми (ASSET-01).
  - Двери, `CargoDoor_L/R`, `PilotDoor_L/R` — отдельные кинематические тела.
  - Рулям, винту, стрелкам и прочим мелким подвижным деталям тела не нужны.
- `SK_UtilityPlane_Cockpit` прикрепить к корню с нулевым трансформом, без физической коллизии.
- Зоны курсора: на старте создать `UBoxComponent` для каждой записи `interaction_volumes.json` (импорт в DataTable).
  - Прикрепить к мешу и кости из записи, смещение `center_cm`, размер `half_extent_cm`.
  - Только Query, канал Interact. Попадание трассы даёт ID = кость или сокет.
- Кости двигает AnimInstance (C++) по реплицированному состоянию через Transform (Modify) Bone. Знаки и диапазоны — `ANIM_CONTRACT.md`. Анимация не бывает источником физики (PHYS-02.1).

### 4.2 Двери — CONFIRMED NEW-04 и DOOR-01

Четыре двери: `PilotDoor_L`, `PilotDoor_R`, `CargoDoor_L`, `CargoDoor_R`. У каждой серверный автомат:

```
Closed → Opening → Open → Closing → Closed
Opening/Closing → Blocked (препятствие) → обратно по команде
```

Грузовые двери:
- Кнопки в кабине — тумблеры `SW_CargoDoor_L/R`: вверх OPEN, вниз CLOSE.
- Привод электрический: нужен ток на шине, ход 100° за 4.5 с (TEMPORARY), потребление 15 А во время хода.
- Без питания дверь открывается только ручкой снаружи (`Socket_Handle_CargoDoor_*_Out`), если самолёт не заперт.

Двери кабины:
- Кнопки в кабине: `SW_CabinDoor_L/R`. **В модели v4 их нет** (§9, пробел M1).
- До модели v5 кнопкой временно служит зона `Socket_Handle_PilotDoor_*_In` (TEMPORARY). Привод и ход — как у грузовых, 70° за 2.5 с.
- Ручки изнутри и снаружи работают тоже (§1.2).

Общее для всех дверей:
- Препятствие: sweep тела двери на следующий шаг хода. При пересечении с грузом, персонажем или миром дверь останавливается в `Blocked`. Сквозь предмет не проходит, предмет не удаляется, импульсы не взрываются (AT-14).
- Звук привода, удар о упор, лязг защёлки.
- Табло:
  - `L08_Door` горит, пока хотя бы одна дверь кабины не в `Closed`;
  - `L09_CargoDoor` горит, пока хотя бы одна грузовая не в `Closed`.

### 4.3 Ключ и центральный замок — CONFIRMED NEW-05

Центральный замок самолёта: состояние `Locked` или `Unlocked`, реплицируется, сохраняется в checkpoint.
- `Locked`: ручки снаружи не открывают двери, звучит «заперто». Кнопки и ручки изнутри работают всегда: изнутри замок не мешает.
- Ключ `BP_PlaneKey` — физический предмет в мире. Меша в модели нет: TEMPORARY простой меш.
  - Его можно поднять, положить, передать другому игроку и потерять.
  - Кто держит ключ, решает сервер. Инвентарь отложен (спека CONTAINER-01 / O-03), поэтому TEMPORARY: один «карман» под ключ у персонажа, без UI инвентаря.
- Замочная скважина — ручки дверей кабины снаружи (`Socket_Handle_PilotDoor_L_Out` / `_R_Out`).
  - «Использовать» с ключом переключает `Locked` ↔ `Unlocked`: звук замка, мигание маяка (TEMPORARY).
  - Без ключа — подсказка «Заперто».
- Запереть изнутри — **OPEN**. По умолчанию нет: запирается только ключом снаружи.
- Потеря ключа не должна создавать тупик. Если кто-то внутри, он открывает дверь кнопкой. Если внутри никого — **OPEN** (запасной ключ на базе как вариант).

## 5. Реалистичная лётная модель — CONFIRMED NEW-03 + PHYS-01/02

### 5.1 Архитектура — ENGINEERING

- Силы считаются в C++ с фиксированным шагом 120–240 Гц: подшаги физики или асинхронный физический тик Chaos. Выбрать измерением в P02/P03 и записать решение.
- Силы прикладываются к телу `Body` (AddForceAtLocation / AddTorque). Позицию и поворот напрямую не задавать.
- Скорость потока в каждой точке — относительно воздуха, с учётом вращения: `v_air = v_cg + ω × r − v_wind(точка)`. Ветер берётся из EnvironmentProvider в точке крыла, а не у камеры.
- Один источник правды для ввода: команды → приводы с ограниченной скоростью (рули ≈ 60 °/с) → силы. Анимация костей рулей берёт отклонение приводов, а не ввод.
- Все единицы подписаны. Внутри модели — СИ (м, кг, с, рад). Переход в см UE — только на границе.

### 5.4 Двигатель и запуск

Запуск короткий (INPUT-01), но физически последовательный:
1. SW_Battery ON.
2. Кран хотя бы одного бака ON, `Pull_FuelShutoff` утоплена.
3. SW_FuelPump ON.
4. SW_Ignition ON.
5. Держать SW_Starter: Ng растёт.
6. При Ng ≈ 13 % подаётся топливо, воспламенение, скачок ITT.
7. При Ng ≥ 52 % двигатель выходит на самоподдержание, стартер можно отпустить.
8. GEN OFF гаснет, когда генератор включается в сеть (Ng > 55 %).

Детали:
- `Lever_Condition`: TEMPORARY — по умолчанию «малый газ». Положение «останов» перекрывает топливо в двигатель и глушит его.
- `Lever_Prop`: TEMPORARY — по умолчанию максимальные обороты. Ручная регулировка допускается, но не требуется.
- Двигатель останавливается, если топливо не доходит: закрыты краны, вытянута перекрывная тяга, баки пустые, рычаг останова.
- Перегрев: ITT выше предела → лампа ENG HOT и обратимое снижение мощности. Постоянной поломки нет, повреждения отложены (DEFERRED).

### 5.6 Топливо

- Два бака, у каждого кран: `FuelSel_L/R`.
- Двигатель получает топливо, если:
  - открыт хотя бы один кран с топливом в баке;
  - перекрывная тяга утоплена;
  - есть напор — насос включён или самотёком от высокоплана, при самотёке TEMPORARY ограничение по расходу.
- Выработка идёт из открытых баков поровну. Дисбаланс баков смещает центр масс и даёт крен.
- Масса топлива — в общей массе и в моментах инерции.
- Заправка по спеке CONTAINER-01: канистра, открытая крышка `FuelCap_L/R`, перелив ровно один раз, вместимость соблюдается.
- Горловины на высоте 2.87 м — **OPEN** (§9, M5).

### 6.3 Приборы — модели датчиков, ENGINEERING

- Стрелки по формулам `ANIM_CONTRACT.md`, с пружиной и перелётом: ω ≈ 10–12, ζ ≈ 0.6. От оборотов двигателя — лёгкая вибрация.
- **Указатель скорости (ASI):** из динамического давления, IAS в узлах.
- **Высотомер (ALT):** из статического давления ISA и давления, выставленного на высотомере.
- **Вариометр (VSI):** запаздывание ≈ 1.5 с.
- **Авиагоризонт (ATT):** электрический. Раскрутка 60 с после подачи питания, без питания медленно заваливается.
- **Указатель поворота (TC):** угловая скорость рысканья, шарик — боковое ускорение.
- **Курсовой (HDG):** гироскопический, с уходом 3–5 °/ч.
- **Двигатель, топливо, амперметр, наружная температура, часы:** из соответствующих систем.
- **Экраны авионики без изменения модели.** В `M_PlaneGauges` добавить маску по UV-прямоугольникам ячеек атласа `T_Gauges`: GPS/COM — ячейка 17, транспондер — 19, автопилот — 22.
  - Внутри маски выводить Render Target с UMG-экраном.
  - GPS: путевая скорость, путевой угол, высота GPS, координаты или простая карта-трек.
  - Экран горит только с SW_Avionics и питанием шины.
  - Функции автопилота — **DEFERRED**, экран показывает только индикацию.
- Постоянного HUD нет. Отладочная телеметрия — только за флагом разработчика.

## 7. Сеть — по спеке §6

Реплицируемое состояние самолёта — компактные структуры:
- органы управления и приводы;
- положения переключателей: запрошенное и фактическое;
- двигатель: Ng, ITT, крутящий момент, обороты винта, давление и температура масла;
- электрика: заряд, напряжение, ток, генератор;
- топливо по бакам;
- двери: состояние и угол;
- замок;
- ремни;
- лампы (битовая маска);
- огни (маска и фаза вспышек).

Правила:
- Представление восстанавливается из состояния, а не из одноразовых событий (AT-24).
- Персонаж — предсказание CMC.
- Режим сетевой физики самолёта и груза — по решению P02.
