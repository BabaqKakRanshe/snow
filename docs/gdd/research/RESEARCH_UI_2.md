# SNOW — интерфейс, заход 2: почему HUD выглядит «сделанным нейросетью» и что вместо него

Дата: 2026-10-23. Продолжение [RESEARCH_UI.md](RESEARCH_UI.md). Источники перечислены в конце, ссылки в тексте даны как [N].

Пометки:
- **[проверено]**: открыл первоисточник (документация, страница лицензии, файл шрифта, статья разработчика) и проверил сам.
- **[вторичный]**: пресса, фан-вики, форумы, описания модов, поисковые сниппеты.
- **[не проверено]**: по памяти, поиском не подтверждал. Перед цитированием перепроверить, лучше глазами в игре.
- **[предложение]**: мой вывод для Snow, разработчик его не утверждал.

Game UI Database [34] по-прежнему отвечает ботам 403 (проверил 23.10), поиск её страниц не индексирует. Новых id не нашёл, ниже даны только известные из первого захода. Скриншоты оттуда нельзя подавать в codex-imagegen (условия сайта).

Кадр Snow: 360 строк (`psxHeight = 360` в `SkyIslandPlayerCamera.cs`), при 16:9 это **640×360**. Дальше «строка» и «px кадра» значат пиксель этого кадра. На 1080p он равен 3×3 px экрана.

## 0. Короткая выжимка

| Вопрос | Главное |
|---|---|
| Почему «как нейросеть» | В текущем HUD собраны почти все приёмы из каталогов «примет ИИ-дизайна» [1]: одинаковая полупрозрачная карточка на каждом элементе, цветная полоса сбоку карточки (в [1] это «самая узнаваемая примета»), тонкая светлая рамка, шрифт по умолчанию, все клавиши в одинаковых коробочках, жёлтый акцент на тёмном. Добавляется проблема, специфичная для игр: UI нарисован в другой плотности пикселей, чем кадр (1080p поверх 360), поэтому выглядит наклейкой. |
| Чем лечат | У интерфейса должен быть голос из мира игры (Coates: UI — это «visual identity», он может «hijack the game's visual identity» [2]). Конкретно: 3 опоры и мотивы из лора, цвет и форма со смыслом [3]. Меньше контейнеров. Один пиксельный сетчатый шрифт с причиной выбора. UI на сетке кадра. Движение, квантованное по кадрам. |
| Как делают PSX-игры | Signalis: целочисленный масштаб «Pixel Perfect», HUD в бою почти нет, предмет применяется через всплывающий вопрос [9][10]. Lethal Company: весь UI одним шрифтом 3270 (IBM-терминал), и пикселизация кадра действует на UI тоже [6]. Obra Dinn исходно рисовалась в **640×360**, то есть ровно в нашем кадре, и Pope ставил разборчивость выше всего [11]. Inscryption ради разборчивости в низком разрешении убрал с карт весь текст, кроме названия [4]. |
| PSX-сетка в Unity | UI рисовать в тот же RT 640×360 (Canvas Screen Space – Camera на камере с targetTexture или UI Toolkit Panel Settings → Target Texture [14][15]). Шрифт — TMP-атлас в режиме **RASTER_HINTED** с Custom Size, равным размеру ячейки [13]. Point-фильтр, Canvas Scaler Constant Pixel Size ×1. Обводку запекать в растровый атлас: Font Style для bitmap-атласов поддерживается [13]. |
| Шрифты с кириллицей | Проверены по файлам и метаданным. **PxPlus** из Oldschool PC Font Pack: кириллица и умляуты есть, CC BY-SA 4.0 [17]. **Terminus**: OFL, 6×12…16×32 [18]. **Unscii** 8×8/8×16: PD, полный А–я [20]. **Fixedsys Excelsior** 8×16: PD/CC0, кириллица есть [22]. **TT2020** (машинка): OFL, кириллица и ß есть [24]. Из Google Fonts кириллица есть у Press Start 2P, Tiny5, Pixelify Sans, DotGothic16, Handjet и PT Mono. **Нет** у Silkscreen, VT323, Jersey, Micro 5, Courier Prime, Special Elite, Barlow, Space Mono [25]. **Spleen**: кириллица на странице не заявлена [19]. **Cozette**: кириллица только в планах [21]. |
| Размеры | В кадре 360: ячейка 8 строк ×3 = **24 px** на 1080p (выше минимума XAG 18 px). Ячейка 16 строк = 48 px, это для записок и терминала. 5-строчные шрифты (Tiny5) дают 15 px, это ниже минимума, для текста не годятся. |
| Направления | Три новых [предложение]. **D1 «Строка 360»**: только текст на сетке кадра, без плашек и коробок. **D2 «Надписи в мире»**: подсказки и названия живут в 3D рядом с объектами и проходят через PSX-конвейер. **D3 «Протокол»**: колонка-журнал событий слева, машинописный шрифт, сначала немецкая строка, под ней перевод. |

## 1. Почему HUD читается как шаблон / «ИИ-сделанный»

### 1.1 Что говорят источники

- **Каталог Impeccable** (Paul Bakaus) [1] [проверено]. Он про веб-интерфейсы, а не про игры, но приметы совпадают с нашим HUD один в один:
  - *Side-tab accent border*: цветная полоса на одном боку карточки «делает обычную карточку похожей на алерт». В описании проекта это названо самой узнаваемой приметой ИИ-интерфейсов [1] [вторичный: формулировка из сниппета документации].
  - *Glassmorphism everywhere*: blur, стекло и свечение как украшение, а не как решение задачи слоёв.
  - *Hairline border with wide shadow*: тонкая рамка и тень одновременно обозначают один край.
  - *Nested cards*, *identical card grids*, *monotonous spacing*: одинаковые карточки и одинаковые зазоры прячут, что с чем связано.
  - *Overused font*: шрифты по умолчанию делают несвязанные продукты похожими.
  - *Dark mode with glowing accents*, *AI color palette*: свечение и стандартные акценты на тёмном фоне.
  - *Bounce/elastic easing*, *pulsing status dot*: декоративное движение без события.
- **Edd Coates** (автор Game UI Database), доклад на PG Connects London, 15.02.2022 [2] [проверено]. У UI три роли: помогать взаимодействовать, показывать сложные указания и быть *«the visual identity and branding»*. *«UI has the power to hijack the game's visual identity»*. Про Persona 5: *«This game wants you to recognise the UI»*. Про Sonic Forces: UI «based on Russian constructivism» и связан с сюжетом. Некрасивый UI может *«make your product look cheap and poorly-made»*.
- **Cait Goodale** (UI-лид, King / Glowmade), «How to write a UI art bible» [3] [проверено]. Выбрать **3 опоры** (pillars), одна обычно — доступность. Решить, видит ли интерфейс персонаж. Записать **мотивы и узоры из лора**. «Always start with colours»: у каждого цвета должен быть смысл. Формы (скруглённые, острые, блочные) тоже имеют смысл. У движения есть таблица таймингов и easing.
- **Daniel Mullins** про Inscryption [4] [проверено]: из-за низкого разрешения «small details on the cards were hard to see», поэтому с карт убрали весь текст, кроме названия, и при нужде закрывали портрет иконками. Ограничение кадра здесь сформировало стиль UI, а не мешало ему.
- **Т. Čeháková**, бакалаврская работа ВШЭ Прага, 2026, «The Line Between Stylistic Intent and Problematic UI in PSX-Style Action Games» [5] [проверено: аннотация]. Сравнивает RE, Dusk, Crow Country, Iron Lung и Ultrakill. Вывод: PSX-эстетика не вредит удобству, **если информационный слой визуально отделён** от «испорченной» графики мира. Вводит «point of break» — момент, когда стилизация начинает мешать базовым действиям.
- Robert Kurvitz про Disco Elysium [36] [проверено]: реплики идут колонкой, текст «tumbles up» как в ленте Twitter. Пример того, как раскладку UI берут из неожиданного источника, а не из шаблона «RPG-окно диалога».

### 1.2 Приметы шаблона в текущем HUD Snow

| # | Примета | В Snow сейчас | Почему выдаёт шаблон |
|---|---|---|---|
| 1 | Одинаковый контейнер на всём | Тёмная полупрозрачная плашка со светлым краем у каждого элемента | В мире такой формы нет. Одна плашка на всё — значит, никто не решал, как выглядит каждый тип информации [1][3] |
| 2 | Полоса-акцент сбоку карточки | Жёлтая полоса 3 px слева | Самая узнаваемая примета [1]. Смысла (тревога, тип) у неё нет |
| 3 | Коробочки вокруг клавиш | Каждая клавиша в жёлтой рамке «[E]» | Удваивает количество прямоугольников. На PS1 клавиш-коробочек не было: были глифы кнопок или просто текст [не проверено] |
| 4 | Шрифт по умолчанию | Arial-подобный, сглаженный | У шрифта нет голоса [1]. Он не из 1990-х и не из Германии |
| 5 | Две плотности пикселя | UI в 1080p, кадр 640×360 ×3 | Мир «крошится» по сетке 3×3, а текст гладкий. Глаз читает это как наложенный стикер. Lethal Company и Signalis держат UI на сетке кадра [6][9] |
| 6 | Тонкая светлая рамка | Hairline на каждом блоке | Примета [1]. После апскейла ×3 рамка 1 px тоньше пикселя мира |
| 7 | Акцент не из палитры мира | Тёплый жёлтый на тёмном | Цвет без смысла [3]. В ночном лесу Snow такого жёлтого нет |
| 8 | Уголки вокруг объекта | Скобки при наведении | Стандартный «прицел sci-fi» [не проверено, моё мнение]. Не связан с 1990-ми и станцией |
| 9 | Ряд из 8 одинаковых ячеек | Хотбар 1–8 | Identical card grid [1]: восемь равных коробок при обычно 1–2 занятых карманах |
| 10 | Нет движения или стандартный fade | Плашки появляются и исчезают | Движение не квантовано по кадрам PS1. Гладкая альфа на крошащемся кадре выглядит чужой |
| 11 | Глагол без объекта | «[E] открыть» | Шаблонная фраза. Глагол + объект («открыть шкаф») звучит как игра, а не как движок |

### 1.3 Противоядия (общие для всех направлений)
1. **Одна причина на каждый элемент.** Для подсказки, сообщения, кармана, записки и чеклиста записать: откуда это в мире Snow (станция, экспедиция, 1990-е, Германия) [3].
2. **Убрать контейнеры.** Текст держится на жёсткой обводке 1 px кадра (3 px на экране), а не на плашке. Плашка остаётся только там, где она — предмет: бумага, экран.
3. **Пиксельная сетка кадра.** Весь экранный UI кратен 3 px на 1080p и лежит в RT 640×360 (раздел 3).
4. **Палитра из мира**, квантованная в 15 бит, как у PS1 [12]. Максимум 3 цвета: текст, обводка, «опасность».
5. **Асимметрия по сетке.** Выравнивание по левому краю title-safe (32 px кадра), разные отступы внутри групп и между ними [1].
6. **Квантованное движение.** Появление за 1–2 кадра (ступенькой или дизер-маской), печать текста по символам, никакого elastic.
7. **Голос текста.** Немецкий как мотив станции (таблички, коды), короткие технические формулировки.

## 2. Референсы: как PSX-подобные и маленькие хорроры делают UI

Формат: что делает игру «авторской» → источник. Где деталей визуала не нашёл, это помечено.

**Signalis** (rose-engine, 2022) [9][10]
- Настройка «Pixel Perfect» (по умолчанию): каждый пиксель игры — одинаковый квадрат на экране. Pixel Scale Auto выбирает наибольший целый множитель, есть и фиксированные ×1/×2/×3. CRT-режим требует ≥1080p [9] [вторичный: фан-вики].
- HUD в исследовании почти нет. Ключевой предмет применяется через короткий всплывающий вопрос, без перехода в инвентарь. Экран инвентаря стилизован под систему андроида-героини [10] [вторичный].
- [не проверено] Красно-белая палитра на чёрном, подписи на немецком и китайском, экран инвентаря как ЭЛТ-терминал. GUIDB: страница не найдена.

**Lethal Company** (Zeekerss, 2023) [6][7][8]
- Весь UI набран одним шрифтом **3270font** (по мотивам терминала IBM 3270), терминал корабля тоже. Пикселизация кадра действует и на UI [6] [вторичный].
- Внутреннее разрешение 860×520 [7] [вторичный: моды и разработчик-подражатель]. У визора шлема отдельная 3D-модель [8] [вторичный]. Подражатель рисует UI отдельной перспективной камерой мешами, а не спрайтами, ради покачивания и глубины [7].
- [не проверено] Оранжевый одноцветный HUD, скан-метки привязаны к объектам в мире.

**Return of the Obra Dinn** (Lucas Pope) [11] [проверено]
- Исходно **640×360**, позже 800×450, потому что крупные пиксели на весь экран утомляли. Приоритет — *«legibility above all else»*, контуры геометрии, дизер — *«as little as possible»*. Для Snow это прямой прецедент той же сетки и того же риска.

**Inscryption** [4] [проверено]: в низком разрешении текст на картах сокращён до названия, остальное отдано иконкам.

**Crow Country** (SFB Games, 2024) [32] [вторичный]: внешность и подача эмулируют ранние survival horror для PS1. Инвентарь открывается по L1, в нём сетка ячеек и карта [вторичный: обзоры]. [не проверено] Крупный округлый шрифт, мягкие пастельные рамки, UI «игрушечный» и этим отличается от мрачного кадра.

**Mouthwashing** (Wrong Organ, 2024), GUIDB [id=2229](https://www.gameuidatabase.com/gameData.php?id=2229) [не проверено]: HUD почти нет, короткие подсказки у центра, текст как часть монтажа сцены. Шрифт не нашёл.

**Iron Lung** (D. Szymanski, 2022) [вторичный, RESEARCH_UI [20]]: интерфейс — это сама подлодка: карта, координаты вручную, датчики, чёрно-белые фото. Экранного HUD нет.

**Buckshot Roulette** (Mike Klubnika) [27] [вторичный: декомпиляция по словам игрока]: реплики дилера набраны **Fake Receipt** (шрифт кассового чека), используется и **DOTMATRI** (матричный). Шрифт взят из быта, а не из «игровых».

**Faith: The Unholy Trinity** (Airdorf) [28] [вторичный]: графика уровня Apple II / Atari 2600, «wickedly chunky pixels». [не проверено] Текст крупным блочным шрифтом, оцифрованная речь. Ограничение платформы доведено до предела, и UI выдержан в нём же.

**Bloodborne PSX** (Lilith Walther) [29] [вторичный]: «clunky UI elements» нарочно, как откат удобств эпохи PS1 ради исследования. UI копирует логику эпохи, а не только её вид.

**Puppet Combo** (Murder House, Nun Massacre) [30] [вторичный]: опции «как ЭЛТ» и «VHS tracking», сохранение карандашами в ограниченном количестве, титульный экран как VHS-кассета. [не проверено] Текст белый, без плашек, поверх VHS-шума.

**Cruelty Squad** (Consumer Softproducts) [31] [вторичный]: вид «low-budget game from a PC CD-ROM from the 90s», UI нарочно перегружен и неприятен. Стиль как позиция, а не как недосмотр.

**Content Warning** [не проверено]: главный UI — видоискатель камеры (REC, время, заряд). **Fears to Fathom** [не проверено]: задачи короткой строкой в углу, телефон и ПК в мире. **Voices of the Void** [не проверено]: работа в «софте станции» на мониторах в мире. **The Mortuary Assistant** [не проверено]: процедура в мире, планшет и компьютер морга. **Dread Delusion** [не проверено]: деталей не нашёл. **Haunted PS1 Demo Disc** [не проверено]: общий приём сцены — одноцветный растровый шрифт в разрешении кадра. **Pacific Drive**: приборы в машине, см. RESEARCH_UI §2.2 [проверено там].

**Общее у удачных:** (1) UI и кадр на одной сетке или UI явно внутри мира. (2) Один шрифт с происхождением: терминал IBM, кассовый чек, система андроида. (3) Почти нет постоянных контейнеров. (4) Ограничение (разрешение, палитра) задаёт форму UI, а не прячется под гладким оверлеем [4][11].

## 3. UI на пиксельной сетке PSX

### 3.1 Как это было на PS1 [проверено, 12]
- Режимы вывода: 256 / 320 / 368 / 512 / 640 по горизонтали, 240 / 480 по вертикали. Рисование всегда в 15 бит (5 бит на канал).
- Дизер — блоки 4×4 со смещениями от −4 до +3, и **только для гуро- и модулированных полигонов**. Плоские (flat) текстурные спрайты без модуляции не дизерятся. Поэтому текст на PS1 обычно чистый, без дизера, хотя лежит в том же кадре [вывод из 12].
- Аппаратного текста нет, шрифт — растровая текстура в VRAM, которую рисуют спрайтами [не проверено, общая практика].

### 3.2 Варианты для Snow
| Схема | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. UI в RT 640×360** (рекомендую) | UI-камера или Canvas рисует в тот же RT **после** PSX-квантования, затем ×3 nearest | Пиксель в пиксель с миром, обводка 1 px = 3 px экрана, дёшево | Дробные экраны (Deck 800, 16:10 1200). См. 3.4 |
| B. Отдельный UI-RT 640×360, композит поверх | Как у подражателя LC: свой RT, затем сложение с кадром [7] | Можно дрожание и перспективу, не трогая мир | Ещё один RT и проход |
| C. Нативный 1080p, всё кратно 3 | Шрифт рисуется ×3 с привязкой к сетке 3 px | Чётко на любом экране | Легко «съезжает» с сетки на 1 px, и снова выходит наклейка |

Дизер на UI: **не дизерить**, как на PS1 (3.1). Цвета UI заранее брать из 15-битной палитры (каналы кратны 8: `#F8F0E0`, `#080810`), тогда квантование их не меняет [предложение].

### 3.3 Unity 6: практические шаги [проверено, кроме помеченного]
1. **uGUI.** Canvas в режиме *Screen Space – Camera*: рисуется «как на плоскости перед камерой» [14]. Камера UI с `targetTexture` = PSX RT (или отдельный UI-RT), Culling Mask только UI. То, что Canvas при этом попадает в RT камеры, — стандартное поведение камеры, в документации Canvas прямо не написано [14] [вторичный].
2. **Canvas → Pixel Perfect** (только для Screen Space): *«rendered without antialiasing for precision»* [14]. Canvas Scaler в режиме Constant Pixel Size, Scale = 1. Все координаты целые.
3. **UI Toolkit** (альтернатива): Panel Settings → **Target Texture**, который *«takes precedence over the target display»*. Scale Mode = Constant Pixel Size, Scale 1 [15].
4. **Шрифт TMP.** Font Asset Creator, Render Mode **RASTER_HINTED** (*«non-antialiased bitmap and aligns character pixels with texture pixels»*). Sampling = **Custom Size**, равный высоте ячейки (8 или 16) — так в документации рекомендуют для bitmap-шрифтов [13]. Атлас: Filter Mode = Point, без mipmaps и без сжатия. Размер текста в TMP — ровно размер сэмплинга, ×1.
5. **Обводка.** SDF-обводка TMP к растровому атласу не применяется. Font Style (в том числе Outline) работает **только** при создании bitmap-атласов [13]. Второй вариант: UI в своём RT плюс шейдер дилатации альфы на 1 px — точная пиксельная обводка любого элемента [предложение].
6. **Pixel Perfect Camera URP** с *Upscale Render Texture* — это компонент для 2D Renderer [16] [вторичный]. Для 3D-кадра Snow не нужен, у нас свой RT.
7. **UI Toolkit, растровый текст** в новых версиях Unity 6 [не проверено]: проверить в редакторе, есть ли у FontAsset режим Raster для панелей. Иначе uGUI + TMP.

### 3.4 Дробные экраны
- Signalis решает целочисленным Pixel Scale и рамкой по краям [9].
- Для Snow [предложение]: высота RT = `floor(screenH / k)`, где k = `max(1, floor(screenH / 360))`. 1080 → 360 (×3), 1440 → 360 (×4), 2160 → 360 (×6), Deck 800 → 400 (×2), 1200 → 400 (×3). Сетка UI остаётся целой, кадр на 16:10 получает на 40 строк больше. UI выравнивать от краёв title-safe, а не по центру фиксированного 640×360.

## 5. Три новых направления [предложение]

Все три отличаются от текущего («тёмные плашки + жёлтые клавиши») и от отклонённых A (почти ничего, часы, иней), B (гаджеты 1990-х: Dymo, ЖК-часы, светодиоды рации) и C (чистый контекстный HUD с иконками). Общее для всех: UI в RT 640×360, без дизера, палитра 15 бит, title-safe 32 px кадра по бокам и 14 сверху и снизу.

### D1. «Строка 360»: только текст на сетке кадра
**Идея:** интерфейса как графики нет, есть только строки растрового шрифта в разрешении кадра с жёсткой обводкой, как в играх PS1 1997 года.
**Референсы:** Signalis (Pixel Perfect, почти без HUD) [9][10], Lethal Company (один шрифт, пикселизация на UI) [6], Obra Dinn (640×360, разборчивость прежде всего) [11].
**Правила:**
- Шрифт PxPlus HP 100LX 6x8, один кегль на весь HUD. Иерархия — регистром (КАПС для объекта) и цветом, а не размером.
- Цвета: текст `#F0E8D8` (бумажный белый, все каналы кратны 8, то есть точно в 15-битной палитре), обводка `#080810` 1 px кадра в 8 направлениях, «опасность» `#D83020`. Жёлтого нет.
- Плашек, рамок, уголков и коробок нет. Клавиша пишется в строке: `E  открыть ШКАФ`, клавиша тем же шрифтом, но темнее (`#A8A090`).
- Прицел: 1 пиксель кадра. При наведении — 3 пикселя «плюсом». Уголков нет.
- Подсказка: строка по левому краю от прицела +8 px, на 12 строк ниже центра. Вторая строка — второе действие (`G  бросить`).
- Карманы: без ряда ячеек. При Q / 1–8 / G слева внизу на 3 с появляется список из занятых карманов, по одному в строке: `3 КАНИСТРА 10 л`, текущий отмечен `>`. Пустые не пишутся.
- Рука: одна строка справа внизу `В РУКЕ  ФОНАРЬ`, только 2 с после смены.
- Сообщения: по центру низа, как субтитры PS1, до 2 строк по 48 символов, печать 40 симв/с, держится 3 с, гаснет за **2 кадра** (50% дизер-маской, затем 0).
- Записки: на весь экран бумага 640×360 с текстом Terminus 8×16, перевод — отдельный слой. Мир под ней — тот же кадр, затемнённый в 15-битной палитре.
- Чеклист самолёта: текстовые строки `[ ] KRAFTSTOFF  топливо`, `[x]` при выполнении, без иконок.
- Движение: только ступени — появление за 1 кадр, исчезновение за 2. Без easing.
**Почему не шаблон:** нет ни одного прямоугольника. Текст лежит на той же сетке 3×3, что и снег, поэтому выглядит частью кадра. Шрифт с конкретным происхождением.
**Стоимость:** низкая. 3–5 дней: UI-камера в RT, TMP-атлас RASTER_HINTED 8 px с запечённой обводкой, перенос OnGUI → uGUI для подсказки, карманов и сообщений.
**Риски:** «слишком просто», нужен очень хороший шрифт и строгие отступы. На белом снегу держится только на обводке, проверить днём при фарах. Новички без иконок карманов дольше учатся.

### D2. «Надписи в мире»: геометрический UI через PSX-конвейер
**Идея:** подсказки, названия предметов и пункты чеклиста — это текст в 3D рядом с объектом. Он дрожит от vertex snapping, тонет в тумане и темноте вместе с миром. На экране остаются только свой эфир и критичное.
**Референсы:** Lethal Company (скан-метки привязаны к объектам, визор — 3D-модель) [8] [не проверено для скана], Dead Space (голограммы инвентаря в пространстве) [RESEARCH_UI 15], Splinter Cell: Conviction (цели проецируются на стены) [не проверено].
**Правила:**
- Шрифт PxPlus HP 100LX 6x8 в World Space TMP, размер подобран так, чтобы на 1,5 м строка давала 8 строк кадра. Дальше 4 м подписи не видны.
- Подпись слева от объекта на уровне его верхней грани, всегда горизонтально (yaw к камере, без roll). Материал Unlit с минимальной яркостью 60%, туман действует наполовину, чтобы надпись «выходила из темноты», а не пропадала.
- Цвет: обводка тёмная, текст `#F0E8D8`. Действие — второй строкой: `E открыть`. Клавиша без коробки.
- Карман и рука: при смене предмета его название возникает в мире у руки (сокет на модели руки) на 1,5 с и опадает вниз на 4 px кадра за 4 кадра.
- Чеклист самолёта: пункты написаны на самой панели у тумблеров как «пометки мелом», `✓` проставляется при выполнении. Видно всем игрокам (это сетевое состояние панели).
- Записки: бумага поднимается к камере как 3D-объект (заполняет 70% кадра), перевод — строкой D1 внизу экрана.
- Сообщения («Генератор: STÖRUNG»): надпись в мире на источнике, если он виден. Иначе строкой D1 по центру низа.
- Чужие игроки: подписи локальные, у других игроков их нет. Метки другим — только предметами (фонарь, мел) [RESEARCH_UI §3.6].
**Почему не шаблон:** экранного HUD почти нет, но и «пустого экрана с часами» (A) тоже нет: информация есть, только живёт в пространстве и подчиняется свету, туману и дрожанию PS1.
**Стоимость:** средняя. 1,5–2 недели: компонент подписи на Interactable, пул World Space TMP, правила ориентации и окклюзии, сокет на руке, надписи на панели самолёта, проверка в Forest ночью.
**Риски:** читаемость под углом и в тумане. Текст пересекает геометрию (нужен ZTest с небольшим смещением или рендер после мира). На стриме подписи мелкие. Два шрифта масштаба (мир и экран) надо держать в одной сетке.

### D3. «Протокол»: журнал станции колонкой
**Идея:** всё, что случилось, пишется как протокол экспедиции: колонка коротких машинописных строк у левого края, сначала немецкая служебная строка, под ней перевод. Подсказки — последняя, ещё не «напечатанная» строка.
**Референсы:** Disco Elysium (реплики колонкой, текст «tumbles up») [36], Signalis (документы и система андроида) [10], Buckshot Roulette (шрифт из быта — кассовый чек) [27], Iron Lung (журналы терминала) [вторичный].
**Правила:**
- Шрифт TT2020 в атласе 16 px (ячейка 16 строк, 48 px на 1080p) для немецкой строки. Перевод — PxPlus 6x8 (24 px), на 2 px кадра правее.
- Колонка: x = 32 px кадра, ширина ≤ 200 px кадра (~30% экрана), низ на 14 строк выше края. Новые строки снизу, старые сдвигаются вверх по 1 строке за кадр. После 6 строк самые старые гаснут за 2 кадра.
- Строка: `03:14  TÜR VERSCHLOSSEN` / `дверь заперта`. Время — станционное, из часов суток игры.
- Цвета: текст «копирка» `#C8D0E0` (холодный), свежая строка `#F0E8D8`, «опасность» `#D83020` только у слова, не у всей строки. Плашек нет, обводка 1 px.
- Подсказка: последняя строка колонки курсивом-«черновиком» (стиль TT2020 D/E): `› E  öffnen — открыть ШКАФ`. Исчезает при уходе взгляда, в журнал не пишется.
- Карманы: по Tab колонка на 4 с заменяется описью `INVENTAR` — 8 строк `1 —`, `2 KANISTER 10 l / канистра`. Без коробок.
- Записки: страница машинописи на всю высоту, перевод между строками мелким 6×8 серым, как карандашная пометка.
- Чеклист самолёта: колонка временно становится чеклистом `PRÜFLISTE`, пункты вычёркиваются линией 1 px.
- Голос и рация: принятое по рации тоже пишется строкой `FUNK` — так зритель стрима видит, что был эфир.
- Движение: печать 60 симв/с со звуком машинки (один сэмпл, высота ±5%), сдвиг колонки ступенькой.
**Почему не шаблон:** у UI есть голос и место в фикции (протокол станции на немецком), раскладка асимметрична и типографична, а не набор карточек. Сразу ясно, из какого мира игра.
**Стоимость:** средняя. 1–1,5 недели: шина событий → очередь строк, двуязычные ключи в `Snow_Loc_en.txt` (немецкая строка не переводится), два атласа, звук. Логика проста, работы много в текстах.
**Риски:** много текста на экране в динамичный момент. Строки на немецком часть игроков воспримет как шум. Колонка слева может закрывать угол обзора, нужен переключатель «только критичное». Машинописный шрифт в 16 строк крупный, колонка быстро заполняется.

### Сравнение
| | D1 Строка 360 | D2 Надписи в мире | D3 Протокол |
|---|---|---|---|
| Экранных элементов в покое | 1 (прицел) | 1 | 0–6 строк |
| Шрифтов | 1 (+1 для записок) | 1 | 2 |
| Стоимость | 3–5 дней | 1,5–2 нед. | 1–1,5 нед. |
| Главный риск | слишком аскетично | читаемость в тумане | перегруз текстом |
| Сочетаются | основа для D2 и D3 | экранная часть = D1 | подсказки можно взять из D1 |

Порядок проверки [предложение]: сначала D1 — он дешёвый и является базой (UI-RT, атлас, обводка) для D2 и D3. Затем макет D3 на тех же атласах. D2 после выбора, потому что он трогает префабы Interactable.

## 6. Вопросы разработчику
1. Какое направление пробуем первым: D1, D2, D3?
2. UI рисуем в RT кадра (на сетке 360) или оставляем нативный 1080p, но кратный 3?
3. Шрифт: PxPlus (CC BY-SA, нужна строка в титрах) или Unscii / Fixedsys (PD)?
