# Обмен картой Unity ↔ Blender — контракт

Версия 0.1 от 26.10.2026. Шаг 1: объекты. Шаг 2 (земля) — в конце, будет дописан.

## Кто чем владеет

- **Земля** (высоты, покраска, дороги, площадки) — только Blender. Unity землю не правит.
- **Места объектов** — обе стороны. В Unity их меняют только перетаскиванием на сцене.
- Деревья и камни, которые стали деревьями Terrain, предметы (канистра, ключи — появляются в игре) и части внутри объекта (дверь, лампа в доме) — не ходят. Ходит объект целиком.

## Имя объекта — `id`

`<группа>/<модель>#<номер>`, номер считает одинаковые модели по порядку в списке.

| Группа | Откуда объект |
|---|---|
| `Structures` | `prefabs` в `Forest_Layout.json` |
| `Rocks` | `rocks` в `Forest_Layout.json` |
| `ForestYardDress`, `ForestStartDress`, `ForestHutDress`, `ForestBunker`, `ForestRocks`, `ForestTrash`, `ForestWorld`, `ForestParts` | собственные объекты Unity (двор, пост у ворот, хижина, бункер у озера, группы пакетов) |

Пример: `Structures/LightPole#3` — третий `LightPole` в `prefabs`.

Если у записи в `Forest_Layout.json` есть поле `"id"`, оно главнее правила. **Чат с первого же обновления пишет `"id"` в каждую запись `prefabs` и `rocks` и больше их не меняет**: новый объект — новый `id`, удалённый — его `id` больше не встречается. Иначе вставка одного фонаря сдвинет номера всех следующих.

## Файлы

| Файл | Что в нём |
|---|---|
| `Snow/Assets/Snow/Levels/Forest/ForestMoves.json` | сдвиги, сделанные руками: `id`, новое место, место от сборки, кто сдвинул (`unity` / `blender`) |
| `source/world_sync/forest/unity_objects.json` | все объекты с `id` в их итоговом месте на сцене Unity, формат как у `prefabs` (`m`, `p`, `q`, `s`) + `moved` |
| `source/world_sync/forest/moves.json` | копия `ForestMoves.json` на момент выгрузки |
| `source/context/<место>/moves_from_blender.json` | сдвиги, сделанные в локальном Blender |

Оси: как в `Forest_Layout.json` (Unity: x — восток, y — вверх, z — север). Blender (x, y, z) = Unity (−x, −z, y).

## Как ходит правка

**Unity → чат**
1. Двигаешь объект на сцене Forest и сохраняешь сцену. Сдвиг сам записывается в `ForestMoves.json`. Его же записывает меню `Tools / Snow / World Sync / Save My Moves`.
2. Пересборка леса возвращает сдвиг на место: он накладывается после шагов КПП и двора и до шагов, которые расставляют вещи вокруг, поэтому вещи хижины едут вместе с хижиной.
3. `Tools / Snow / World Sync / Export For Blender` → папка `source/world_sync/forest/` → её загружаем чату.

**Чат → Unity**
1. Чат присылает новый `Forest_Layout.json`.
2. Перед установкой: `Tools / Snow / World Sync / Check Incoming Layout…`. Для каждого сдвига отчёт пишет одно из трёх:
   - **забрал Blender** — объект в пакете уже стоит там, куда его сдвинули в Unity, сдвиг больше не нужен;
   - **остаётся** — Blender объект не трогал;
   - **КОНФЛИКТ** — объект сдвинули обе стороны или Blender его удалил. Решает пользователь, молча ничего не выбирается.

**Локальный Blender (Claude у тебя на машине)**
1. `Tools / Snow / Blender Context` → `context.blend`. У каждого объекта с `id` на пустышке-корне (ARROWS) есть `world_id`.
2. Двигать объект за пустышку, а не за его сетки.
3. `blender -b context.blend --python tools/blender_context/export_moves.py` → `moves_from_blender.json`.
4. `Tools / Snow / World Sync / Import Moves From Blender…` → объекты встают на новые места на открытой сцене. Если в Unity объект успели сдвинуть после выгрузки, это конфликт, и его место не меняется.

## Что важно в шаге 1

- Сдвиги начинают записываться после первой пересборки леса с новым кодом: объекты получают `id` только при сборке.
- Некоторые объекты Unity сейчас ставит не туда, куда их поставил чат: КПП перенесён на 260 м по дороге (`ForestRelocationStep`), двор собран в масштабе ×0,7071 (`ForestYardStep`). Для них место в пакете чата и место на сцене разные. Пока эти шаги работают, чат берёт `unity_objects.json` как образец того, что видит игрок, но в свой `Forest_Layout.json` эти места не переносит. Иначе Unity сдвинет их второй раз.
- В шаге 2 чат делает землю целиком и переносит в свой пакет итоговые места всех объектов. В том же обновлении Unity выключает свои шаги, которые двигают объекты и правят землю. После этого место в пакете = место в игре, и сдвиги забираются без оговорок.

## Вся карта — набор для Blender

`Tools / Snow / World Sync / Export Whole Map` → `source/world_sync/forest/map/`. Это не один огромный файл, а набор:

| Файл | Что в нём |
|---|---|
| `ground.r16` | высоты всех плиток Terrain одной сеткой (uint16, строки с юга на север), шаг и min/max — в `map.json` |
| `holes.u8` | дыры в земле: 1 = земля, 0 = дыра |
| `paint.png` | покраска земли, 1 px на метр, север сверху |
| `meshes.bin` + `textures/` | каждая модель один раз, уже в осях Blender |
| `map.json` | объекты (корень + меши, `id` на корне), деревья Terrain (`trees.bin`: модель, место, поворот, размер), лампы |
| `build_map.py` | собирает `map.blend`: землю, объекты, деревья через Geometry Nodes |
| `export_moves.py` | сдвиги объектов обратно в Unity |

Собрать: `blender -b --factory-startup --python build_map.py -- map.json map.blend`. Земля по умолчанию через точку (`--ground-step 2`), `--ground-step 1` — полная.

## Земля из Blender в Unity

1. Правишь вершины `Ground` в `map.blend` только вверх и вниз: не добавляешь и не удаляешь вершины, сам объект не двигаешь. Сохраняешь копию, например `edits/<правка>/map_edit.blend`.
2. `blender -b map_edit.blend --python export_ground.py -- <папка>` → `ground_delta.f32` + `ground_delta.json`. Разница с исходной землёй разносится на полную сетку, мелкий рельеф сохраняется.
3. Unity: `Tools / Snow / World Sync / Import Ground From Blender…`. Что он делает:
   - проверяет, что плитки не менялись с выгрузки, и копирует их в `snow_archive/backup/forest_ground_import_<дата>`;
   - поднимает и опускает землю;
   - деревья на изменённой земле ставит на неё;
   - новую землю (изменилась на 1 м и больше) засаживает лесом как вокруг: породы и густота соседних деревьев, без копирования рисунка, не под постройками и не на склонах круче 30°. Покраска и трава — средние по соседнему лесу;
   - камни из пакетов едут вместе с землёй;
   - сохраняет правку в слой ручных правок `Forest_HandSculpt.bytes`, чтобы её не стёрла повторная выпечка земли.
4. Постройки, которые надо поднять на новую землю, двигаются в том же `.blend` и уходят через `export_moves.py`.

Первая правка: `tools/blender_context/edits/forest_fill_east_channel.py`, засыпка двойного русла за базой (27.10.2026).

## Шаг 2 — земля (черновик, согласовать с чатом)

- Высоты всей карты 1800 × 1800 м одним файлом: 16-бит PNG или EXR, точка через 0,6 м (3 073 × 3 073), плюс min/max высоты в метрах.
- Покраска: маски PNG (дорога, гравий, мох, вырубка), 1 px = 0,5 м или крупнее.
- Где растёт лес: маска плотности. Деревья расставляет Unity.
- Площадки под постройки делает чат: ровное место + откос 1 : 2 + край (камни, бордюр).
