# УАЗ «буханка» (van3) в игре — задание для Unity-агента

Версия 1, 21.10.2026. Пакет: `source/vehicles/Van_Unity_v1` (модель, данные, риг, сборка префаба). Итог задания —
**машина игроков, на которой можно уехать**: стоит в лесу у `Car_Start`, игроки садятся, по-настоящему заводят её
(масса, зажигание, топливо, аккумулятор, подсос, холод), едут по снегу на автоматической коробке, включают свет с
формой лучей по IES, работают двери, люки, крышки, рычаги и весь комплект; всё согласовано у четырёх игроков.

## 0. Как работать

Основа требований — `docs/gdd/VEHICLE_SYSTEM_AI_SPEC.md` (далее «спец»): SEAT, INPUT, VIEW, SYS, DOOR, ALERT, PHYS,
WEATHER, CARGO, NET, SAVE, DEFERRED, ARCH, приёмочные AT-xx. Общие правила работы в Unity, статусы и формат
отчёта — `docs/gdd/PLANE_PROMPT_UNITY.md` (версия 2.1, §0). Модель и названия деталей — `docs/gdd/VAN3_CONTRACT.md`.

**Объём.** Этап спеца P09 говорил «грузовик и снегоход — не сейчас». 21.10.2026 пользователь попросил встроить
машину сейчас: это задание отменяет P09 **только для этой машины**. Снегоход по-прежнему не делать.

Статусы: **CONFIRMED** — решено пользователем или спецом; **TEMPORARY** — стартовое значение, настраивается на
стенде, записывается в `docs/dev/Tuning/Van.md` с единицами, источником и замером; **OPEN** — не решено, действует
временное решение из §9, спрашивать только если блокирует этап; **DEFERRED** — не делать.

Обязательно:

1. Переиспользовать системы игры: `SeatedVehicle` / `SeatAnchor` / `SeatController` / `ControlInput`,
   `InteractionHost` / `InteractionSensor` / `PlayerNet.UseRpc → ServerUse`, `NetworkDoor`, `CargoItem` /
   `StowPoint` / `TieDownSocket` и рецепт NetItem, `BenchLog` / `BenchBot`. Не копировать систему самолёта под
   другим именем (P09). Самолёт и уровни не ломать: после каждого этапа — его стенд и тесты зелёные.
2. Сервер считает всё (вариант A физики, как самолёт и `BenchCarrier`); клиенты шлют намерения и видят
   реплицированное состояние. Презентация (`VanRig`) — только отображение.
3. Пакеты не устанавливать. Настройки URP / Quality — только проверять; если чего-то не хватает (Depth Texture,
   тени дополнительных источников, cookies, Light Layers) — сообщить пользователю, что и где включить.
4. Не менять файлы пакета в `Snow/Assets/Van` руками, кроме повторного запуска меню сборки. Всё игровое — в
   `Snow/Assets/Snow/...`. Нашли ошибку пакета — записать в `docs/dev/Van/PackageIssues.md` (что, где, как обошли).
5. Небольшие законченные шаги; после каждой итерации — отчёт по шаблону (`PLANE_PROMPT_UNITY.md` §0) и запись в
   `docs/dev/ImplementationStatus.md`. «Написано», «собрано», «запущено», «проверено в сети» — разные вещи.
6. Подсказки и подписи интерфейса — по-русски, как сейчас в игре (подписи зон уже в `zones.json`). Надписи на
   самом оборудовании (текстуры) — английские; таблички на стенах — немецкий + английский (правило проекта).
   Оружия нет.
7. Перед началом — коммит в git (одна точка отката). Файлы не удалять. `Player.prefab` и `BenchBuilder` не менять
   (свой стенд — новым `VanBenchBuilder`). Первую сцену в Build Settings не менять, кадр PS1 у игрока не
   выключать. Сетевые проверки с виртуальными игроками: Join в их окнах нажимает пользователь — попросить.

### 3.1. Поток данных

Клиент: ввод в кресле (`SeatController` → `AxesRpc`, 30 Гц, ненадёжно) и использование зон (`UseRpc`) → сервер:
`ServerAxes` (только место водителя) → `VanMotion.Step(dt)` в `FixedUpdate` (1/120 с) → силы в `Rigidbody`;
`VanSystems.Step(dt)`; `ServerUse` → `VanControls` → `VanState`. Все пиры: `VanState` → `VanPresentation` → `VanRig`.

### 3.2. Сеть (NET-01…04)

- Тело — как `BenchCarrier` / самолёт: Rigidbody симулируется на сервере, клиенты — кинематическая копия через
  NetworkTransform / NetworkRigidbody, без предсказания. Двери — `NetworkDoor`.
- Положения деталей: `NetworkList<byte>` по таблице интерактивных деталей (значение в `min..max` → 0…255; для
  поворотных ключей и переключателей — номер положения). Наличие предметов на машине (снятые колёса, свечи,
  предохранители, крышки, ключи) — биты в `NetworkList<ulong>` (как `SkyIslandLocationHost`).
- Телеметрия 10–15 Гц одной структурой: обороты, скорость, угол руля, сжатия подвесок (×4, байт), передача,
  флаги (двигатель, стартер, ручник, тормоз, задний ход, повороты, аварийка), стрелки (топливо Л / П, температура,
  масло, вольтметр), напряжение шины, дворники, огонь печки, обдув. Стёкла (13 × иней / снег / запотевание) и снег
  на машине — 1 Гц.
- Разовые события (ClientRpc, не reliable каждый кадр): отпечаток ладони, `FlickerBurst`, сигнал, стук,
  «чихнул двигатель». Состояние после события всё равно восстанавливается из `VanState` (NET-04).
- Вращение колёс клиент считает сам по скорости колеса из телеметрии (`SetWheel` с бегущим углом).
- Сервер не останавливает симуляцию машины вдали от хоста (NET-04).

### 3.3. Связь с пакетом

- Сборки: в `Snow.Runtime.asmdef`, `Snow.Levels.asmdef`, `Snow.Editor.asmdef` добавить `UazVan.Runtime`.
- Зоны: `InteractionHost` / `InteractionSensor` работают с `UtilityPlaneInteractable`. Проще всего:
  `VanPrefabBuilder` вешает рядом с каждым `VanInteractable` компонент `UtilityPlaneInteractable` с теми же
  `id / kind / label` (остальные поля `VanInteractable` — `side`, `part`, `socket`, `itemType` — читает
  `VanControls`). Новые виды зон (`slot`, `stow`, `item`, `hide`, `cap`, `lock`, `ladder`) датчик должен пропускать
  как обычное «использовать», `rotary` / `selector` — как у самолёта (колесо мыши / клики), `momentary` — с
  отпусканием. Если удобнее обобщить датчик интерфейсом — можно, но самолёт не ломать.
- **Вложенные зоны (обязательно).** Датчик берёт первую зону, в которую входит луч. У машины 75 зон из 231 в покое
  лежат целиком внутри большей (`insideOf` в `zones.json` и у `VanInteractable`): гайки внутри зоны колеса, крышки
  баков внутри `Pour_Fuel_*`, кнопки блокировки и стёкла внутри дверей, сиденья внутри `Sit_*`, инструмент внутри
  `ToolBox`, предохранители и кран баков внутри `Hide_Footwell_*`. Без правила нельзя открыть бак (S3), снять гайку,
  запереть дверь. Правило для хоста машины (у самолёта поведение не менять — флаг хоста, по умолчанию выключен):
  среди зон, в которые луч входит, пока он ещё внутри первой найденной, выигрывает самая маленькая доступная
  (`Usable`: сторона по полю `side`, `ZoneOpen`, крышки). Плюс `ZoneOpen` машины закрывает зоны, которым сейчас
  нечего делать:
  - **крышки** (`coveredBy` у зоны): зона недоступна, пока её крышка закрыта (значение крышки < 50 % хода): крышки
    баков — за лючками, пробка радиатора — за лючком радиатора, предохранители — за крышкой блока, всё двигателя —
    за кожухом `EngineCover`, АКБ и клеммы — за крышкой ящика, а сама крышка ящика — под сиденьем L4 (открыта =
    сложено), инструмент — в ящике, карта / журнал / фонарь / фальшфейеры — в бардачке, розетка — под колпачком,
    отверстие рукоятки — за шторкой, топка — за дверцей печки; пока крышка закрыта, зоны за ней для луча прозрачны
    и выбирается сама крышка (открыть);
  - **сиденья**: пока сиденье разложено, `Sit_*` выигрывает у `Seat_*` (подушка внутри `Sit_*`): наведение на
    подушку — «сесть»; сложить разложенное свободное сиденье — удержание использования 0,6 с на `Sit_*` (датчику
    машины — короткое нажатие / удержание); `Seat_*` доступна, только пока сиденье сложено (разложить);
  - `slot` (заливка, топка, рукоятка, розетка, крючок, буксир, домкрат, лампа под поддоном, щётка по снегу и
    стёклам) — только с подходящим предметом в руках; заливка — ещё и при снятой крышке;
  - колесо (`item`) — снять: все 6 гаек сняты и угол поднят; поставить: колесо в руках, ступица пуста;
  - `stow` — взять: предмет на месте, руки пусты; положить: в руках принимаемый тип (`itemType`), место пусто;
    `ToolBox` и `FuseTin` берутся только пустыми (содержимое контейнеров — DEFERRED, O-03);
  - стекло двери (`Glass_Window_door*`) — только со щёткой в руках, иначе выигрывает окно (`Window_door*`).
  Проверка — AT-V08 по всем зонам.
- Зоны снимаемых деталей (предметы на местах, крышки, свечи, ключи, колёса, гайки) висят **на родителе детали**:
  риг прячет деталь (`SetVisible(false)`), зона остаётся — предмет можно вернуть, ключ — вставить обратно.
- Стёкла: зона `Glass_<имя>` → стекло `<имя>` для `SetFrost / SetFog / AddHandprint` (поле `pane`; лобовое — `lob`).
- `InteractionHost.interiorCenter / interiorSize` = `model_facts.json` (`[0, 1.42, -0.07]`, `[1.80, 1.24, 4.04]`).
  У самолёта сторона зоны — суффикс `_In / _Out` в id; у машины суффиксов нет, сторона — поле `side`
  (in / out / both) у `VanInteractable`: проверку стороны для машины брать из него (сделать её переопределяемой
  в `InteractionHost` или учесть поле), правило самолёта не менять.

### 4.1. Тело

  `StowPoint` — по правилу груза игры.
- Центр масс `[0, 0.88, 0.15]`; явные моменты инерции (как `BenchCarrier`, без демпфирования Rigidbody):
  TEMPORARY `(4300, 4100, 1600)` кг·м² относительно x (тангаж), y (рыскание), z (крен).
- Коллайдеры — 49 коробок пакета (полая оболочка: в салон можно войти) + коллайдеры створок на петлях.
- Сопротивление воздуха `½ρ·CdA·v²`, CdA = 2,2 м² (TEMPORARY), относительно воздуха (ветер — когда появится
  `EnvironmentProvider`; в лесу его нет — без ветра).

### 4.2. Колёса (4 луча, без WheelCollider)

Взять за основу `Snow.Aircraft.WheelContact` (якорь шины, круг трения) — **копией** `VanWheel`, самолёт не трогать.
Отличия:

- **Ход подвески от статики.** В модели колесо стоит в статическом положении под массой — это поза модели, а не
  полный отбой. Статическая нагрузка колеса `F₀` (перед: доля `(0.15 + 1.2031) / 2.4098 = 0,56` от 1950 кг на ось,
  ≈ 5370 Н на колесо; зад ≈ 4190 Н), `k = 42 000 Н/м` → статический прогиб `F₀ / k` ≈ 0,128 м спереди и 0,10 м
  сзади. Луч от центра колеса, поднятого на ход сжатия 0,10 м, длиной `0,10 + F₀/k + r` (r = 0,364); сжатие `c`
  — от полного отбоя, сила `N = k·c` (в позе модели `c = F₀/k`, `N = F₀`; при касании сила растёт от нуля — без
  скачка), демпфер 3500 (сжатие) / 5000 (отбой) Н·с/м, за ходом сжатия — отбойник (×10). Предварительного натяга
  нет: полностью выпущенная стойка — на `F₀/k` ниже позы модели. Если поставить полностью выпущенную стойку
  `WheelContact` в позу модели (как у шасси самолёта), машина сядет на отбойники: прогиб 0,13 м больше хода
  сжатия 0,10 м. Колесо в риге: `SetWheel(i, угол, c − F₀/k)` (+ вверх в арку, − вниз).
- **Привод.** К продольной силе якоря добавить тяговую `F_t = T_колеса / r` до проверки круга трения; превышение
  круга — пробуксовка (колесо крутится быстрее: своя угловая скорость, инерция колеса 1,2 кг·м² TEMPORARY).
  Тормоз — момент колодок (до 2600 Н·м спереди, 1700 сзади на колесо), колесо может заблокироваться (АБС нет).
- **Сцепление с поверхностью** `μ`: по `PhysicMaterial` / слою поверхности под лучом. TEMPORARY: укатанный снег
  0,32 (весь лес по умолчанию), дорога 0,45, рыхлый 0,22, лёд 0,10; цепи +0,12 (снег) / +0,18 (лёд);
  спущенная шина ×0,6, радиус −0,04 м, сопротивление качению ×3. Сэнд-трак под колесом — μ 0,8.
- Сопротивление качению 0,015 (на снегу 0,03, TEMPORARY).
- Руль: Аккерман по базе 2,41 м и колее 1,65 м; ход передних колёс ±32°. Визуально оба колеса — `SetSteer`.

### 4.3. Трансмиссия (INPUT-01: автомат, без педали сцепления)

- Двигатель УМЗ-451М: кривая момента `vehicle.json → engine.torqueRpm / torqueNm` (167 Н·м при 2500), холостые
  600 (регулятор холостого хода держит), отсечка 4200, трение 18 Н·м + торможение двигателем при закрытом дросселе,
  инерция 0,18 кг·м². Дроссель = max(педаль, ручной газ `Knob_Throttle`, регулятор холостых).
- Сцепление-автомат: передаёт `clamp(k·Δω, −T_cap, T_cap)`, `T_cap = 1,3·T_max·smoothstep(900, 1500 об/мин)` при
  включённой передаче; при малом Δω — замкнуто. На месте с нажатым тормозом двигатель не глохнет. Пуск с толкача /
  на буксире: двигатель стоит, зажигание II, передача — окно включения другое: `T_cap = 1,3·T_max·smoothstep(100,
  400 об/мин входного вала)`; на 5 км/ч вал крутится 770 об/мин на 1-й (H) и 490 на 2-й — сцепление замыкается

  `Heater_Fan`, заслонку `Heater_Air` ноги / стекло; печка салона 6 кВт), дыхание людей в каждом объёме →
  запотевание стёкол группы; обдув на стекло снимает иней и запотевание лобового; открытые окна и люк проветривают.
  Результат — `SetFog / SetFrost` на сервере → реплика → риг (спец AT-21).
- Снег: на крыше, козырьке, бампере и фарах копится на стоянке, сдувается на скорости; щётка счищает: зоны `slot`
  `Snow_Roof` (с земли — край крыши), `Snow_Visor`, `Snow_Bumper`, `Snow_Head_L/R`, `Snow_Spot_L/R`, `Snow_Fog_L/R`
  и `Glass_*` (снег и иней снаружи); зона снега пропадает вместе со снегом. Снег на фаре гасит до 85 % света.
  Дворники (`Toggle_Wiper`, предохранитель 8) `rig.wiperSpeed = 40` взмахов/мин и счищают снег с лобового.
- Отпечатки: события `AddHandprint` (рукой изнутри на запотевшем стекле; сценарные — `AddHandprintAtSocket`);
  на всех пирах.
- Зеркало: `rig.mirrorActive = true` только у местного игрока в кабине.
- Зацепки ужаса (сами страшилки DEFERRED): укрытия `Hide_*` (поза пригнувшись в точке; флаг «спрятан»), стуки
  по `Knock_*` (событие со звуком в точке), `lightFlicker` / `FlickerBurst` с общим сетевым временем
  (`flickerClock`), `ServerMisfire`. Проверка — кнопками стенда.

### В8 — лес и приёмка

- Сцена Forest: `VanVehicle` у якоря `Car_Start` (`Forest_Opening.json → car`: p `[-463.1961, 22.8694, 495.643]`,
  q `[0.022677, 0.898151, -0.011083, -0.438962]`) в состоянии `vehicle.json → forestStart`. Точки спавна 1–3
  сейчас внутри машины — TEMPORARY: игроки на старте сидят на местах водителя, пассажира, L1, R1 (S1 начинается
  «в машине»).
- `ForestOpening`: сейчас шаги машины пропускаются (`S1|S3|S4|S5`). Включить их от машины: S1 — все вышли из
  мест; S2 — канистра избушки ближе 3 м к машине; S3 — топлива в баках ≥ 5 л; S4 — двигатель работает; S5 —
  машина ближе 15 м к шлагбауму. Канистра избушки по сценарию заправляет машину — её содержимое бензин
  (TEMPORARY; дизель генератора — отдельно).
- Страшилки X02, X03, X04 — DEFERRED (решение по U6), их не делать. Только зацепки, чтобы потом не трогать
  машину: «фары горят» (выход ламп `Head_L/R` > 0,2), «салон пуст» (места L1–R2), «водитель смотрит в зеркало /
  повернул голову > 120°», точка заднего места для фигуры (`Sit_L4` / `Sit_R2`), `VanVehicle.ServerMisfire(s)`
  («чих»: на s секунд падает момент) и `FlickerBurst` с общим временем — с тестом на стенде, без событий в лесу.
- `Car_Parked` (`[323.26, 16.38, −335.43]`, курс ≈ −87°) — место стоянки на базе (проверить в данных Forest).
- Сохранение (SAVE-01): поза машины, детали, предметы, топливо, заряд, температура, предохранители, ремень,
  стёкла, снег; без дублей при повторной загрузке (спец AT-26). Если системы checkpoint в игре ещё нет —
  структура `VanSaveState` + тест сериализации, само сохранение — когда появится.
- AT-V17 — полный пролог S1–S5 вчетвером (хост + 3 клиента), видео / лог; FPS и время физического шага
  записать.
- AT-V18 — RTT 100 / 200 мс, потери 1 / 3 %: езда, двери, заправка; ошибки позы и коррекции измерены (спец AT-19).

## 7. Презентация (VIEW-01)

`VanPresentation` на каждом пире каждый кадр: детали из `VanState` (`SetPart` / `SetVisible`), руль и колёса
(`SetSteer`, `SetWheel` с подвеской из телеметрии, `SetFlat`), педали и рычаг КПП, стрелки (`SetGauge`: км/ч,
об/мин, доля бака, °C, кгс/см², В), `engineRpm`, лампы (`SetLamp` по цепи с сервера, `busVoltage`, `turnSignal`,
`hazard`, `brake`, `panelLight`, `stoveFire`, `stoveDoor`), стёкла, снег, дворники, рация, `mirrorActive`. Руки
водителя — сокеты `Hand_Wheel_L/R` (как у самолёта: руки следуют за рулём). Звуки — по точкам `audio` и
`FlasherClicked`, если в проекте есть ассеты; иначе — заглушки и OPEN.
