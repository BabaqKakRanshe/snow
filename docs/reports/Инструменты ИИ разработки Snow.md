# Дать ИИ больше работы, себе — больше контроля

Главный вывод: почти всё полезное для Snow — это **небольшие вещи, которые мы пишем сами** поверх того, что уже есть: хуки Claude Code, журнал игры в JSONL, локальная «дверь» в запущенную игру, боты-клиенты и проверки в snow_qa. Готовые платные системы (AltTester, GameDriver, FMOD, Unity Generators, оркестраторы агентов) либо стоят денег, либо повторяют то, что у нас уже есть через Unity MCP и пульт. Скачивать стоит в основном бесплатные утилиты: ffmpeg и Whisper для проверки звука, clumsy для плохой сети, ACE-Step для музыки, Chatterbox или Kokoro для голоса, статуслайн для Claude Code. Самое ценное для вас как человека — **жёсткие проверки через хуки**: ИИ не может сказать «готово», пока консоль красная или пока нет скриншота-доказательства. Самое ценное для передачи работы ИИ — **боты и тесты, которые ИИ запускает и читает сам**, без MPPM и без ваших кликов. На RTX 3080 с 10 ГБ реально запустить музыку (ACE-Step), голос (Chatterbox, Kokoro) и, на пределе, форму 3D от Hunyuan3D. TRELLIS.2 (24 ГБ) и большие «слушающие» модели не поместятся. Важная оговорка: сейчас действует ваше правило «только компиляция, без прогонов», так что пункты с тестами ждут вашего решения (вопрос 1 в конце).

Порядок — по пользе на единицу усилий.

## Агентский процесс: хуки важнее любых сторонних оркестраторов

К октябрю 2026 в Claude Code уже есть всё нужное для контроля. Хуки — это код, который исполняет программа, а не просьба в CLAUDE.md, поэтому их нельзя «забыть». Есть больше 30 событий. Stop, TaskCompleted и PreToolUse могут блокировать действие. Кроме обычных shell-хуков есть `prompt`-хук (короткая оценка Claude) и `agent`-хук (подагент проверяет условия, пока экспериментальный) ([Claude Code hooks](https://code.claude.com/docs/en/hooks)). Для Snow это значит: правило «проверь скриншотом» можно сделать обязательным, а не устным.

Отдать работу ИИ тоже можно, но с оговоркой. Фоновые агенты и облачные задачи по расписанию работают в облаке, где нет Unity, лицензии и моста к вашему редактору ([Claude Code overview](https://code.claude.com/docs/en/overview)). Поэтому в облако — только текст: вопросы GDD, исследования, черновики девлога. Работа со сценами остаётся локальной и по одному агенту на редактор. Это совпадает с вашим правилом «спрашивать перед тем, как занять общий редактор».

Сторонние оркестраторы не нужны. Vibe Kanban остался без компании в апреле 2026 ([aiidelist](https://aiidelist.com/ide/vibe-kanban)), Conductor — только для Mac, Claude Squad требует tmux, то есть WSL ([agentsroom.dev](https://agentsroom.dev/zh/blog/best-multi-agent-coding-tools)). Параллельные агенты над одной Unity-сценой ломают друг другу работу.

## Логи и Unity MCP: игра должна сама рассказывать о себе

Официальный Unity MCP уже даёт ИИ консоль, захват камеры и около 15 инструментов профайлера, но только в **редакторе**. Он не видит собранную игру и клоны MPPM ([Unity MCP overview](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-overview.html)). Эту дыру проще всего закрыть своими силами: игра пишет JSONL-журнал через `Application.logMessageReceivedThreaded` и открывает маленький локальный HTTP только в dev-сборке. ИИ читает его curl-ом или тонкой Python-обёрткой. Это тот же приём, что и ваш bench-порт 7797.

Если когда-нибудь нужен полноценный MCP внутри сборки, есть [IvanMurzak/Unity-MCP](https://github.com/IvanMurzak/Unity-MCP) (Apache-2.0). Он работает внутри собранной игры, но по умолчанию там **нет ни одного инструмента**: всё равно придётся писать свои. CoplayDev/unity-mcp популярен (MIT), но работает только в редакторе и дублирует то, что уже стоит ([GitHub](https://github.com/CoplayDev/unity-mcp)). Два моста к редактору сразу дают путаницу портов и названий.

Sentry подключать стоит, когда сборки уйдут к внешним тестерам. У него есть официальный Unity SDK с нативными крашами на Windows и официальный MCP-сервер `mcp.sentry.dev`, который Claude Code подключает одной командой ([Sentry MCP](https://mcp.sentry.dev/); [Sentry Unity](https://docs.sentry.io/platforms/unity/native-support/)). Бесплатный план — один человек; лимит ошибок в источниках расходится (5 тыс. или 50 тыс. в месяц), это не проверено.

## Тесты: встроенного UTF хватает, внешние драйверы — лишние

Unity Test Framework теперь встроен в движок и запускается из командной строки: `-runTests -batchmode -testResults X.xml`. Результат — XML, который ИИ разбирает напрямую ([Unity: command line](https://docs.unity3d.com/6000.2/Documentation/Manual/test-framework/reference-command-line.html)). Подвох: batchmode не работает, пока проект открыт в редакторе. Поэтому при открытом редакторе ИИ запускает тесты через Unity MCP (`RunCommand` + `TestRunnerApi`; точный API не проверен).

Для сети в пакете NGO есть `NetcodeIntegrationTest`: хост и N клиентов в одном процессе внутри теста ([исходник NGO 1.2](https://plastichub.unity.cn/unity-tech-cn/MetacityTemplate/raw/commit/720f3ddc-bab8-4e90-92bf-5cfac1c70369...Packages/com.unity.netcode.gameobjects@1.2.0/TestHelpers/Runtime/NetcodeIntegrationTest.cs)). Это правильный инструмент для проверок «предмет в кармане виден всем», «двери фургона синхронны», «поздний вход видит предметы». Видели только версию 1.2, API в 2.13 надо сверить в `Library/PackageCache`.

Внешние драйверы не окупаются. Unity Automated QA заброшен с 2021 года ([Unity](https://docs.unity3d.com/Packages/com.unity.automated-testing@latest)). AltTester требует аккаунт и ключ даже на бесплатном плане ([AltTester](https://alttester.com/the-next-chapter-for-alttester-expanding-with-unreal-sdk-and-licensing-updates/)), и он заточен под uGUI и UI Toolkit, а у Snow OnGUI и ImGui. Свои «тестовые ручки» через dev-HTTP дают то же самое.

ИИ как судья скриншотов полезен только как первый фильтр. Исследование 2026 года показало, что VLM дают много ложных тревог, и советует ставить их перед проверкой, а не вместо неё ([arXiv 2607.25921](https://www.alphaxiv.org/abs/2607.25921.md)). Простая проверка яркости кадра поймала бы ваш случай «ночь — чёрная пустота» дешевле любой модели.

## Нагрузка и сеть: боты в окнах без графики вместо MPPM

MPPM даёт максимум 4 игрока ([Unity MPPM](https://docs.unity3d.com/Packages/com.unity.multiplayer.playmode@1.6/manual/index.html)) и не имеет API для автоматизации — это подтвердил сотрудник Unity ([форум](https://discussions.unity.com/t/automated-gameplay-testing-with-multiplayer-play-mode/1626883)). MPPM 2.0 с четырьмя собранными клиентами требует Unity 6000.3, а Snow на 6000.0 ([MPPM 2.0](https://docs.unity3d.com/Packages/com.unity.multiplayer.playmode@2.0/manual/index.html)). Облачный путь Unity Multiplay закрыт с 31.03.2026 ([Unity status](https://status.unity.com/info_notices/362941)).

Значит, путь один: dev-сборка, запущенная N раз с `-batchmode -nographics` ([Unity: headless](https://docs.unity3d.com/Manual/desktop-headless-mode.html)). Маленький C#-компонент бота читает аргументы (`-snowBot`, `-connect`, `-botSeed`, `-runMinutes`, `-metricsOut`), подключается и «играет» тем же вводом, что игрок. Python запускает хост и ботов, ждёт, собирает все JSONL и пишет итог. Сколько ботов потянет один ПК, нигде не измерено — проверим сами.

Плохую сеть проще всего задать флагом `-netSim`. Он включает отладочный симулятор Unity Transport или пресеты Network Simulator: например, «Home Satellite» 100 мс, «Mobile 4G» 100 мс с потерей 4% ([Multiplayer Tools: Network Simulator](https://docs.unity3d.com/Packages/com.unity.multiplayer.tools@2.2/manual/network-simulator.html)). Каждому боту — своя плохая сеть. clumsy (MIT) ломает весь трафик, включая localhost, без правок кода, но это окно с правами админа ([clumsy](https://www.github.com/jagt/clumsy)).

Готового детектора рассинхрона для NGO нет. Игроки Lethal Company годами жалуются на монстров, которые расходятся с хостом ([Steam](https://steamcommunity.com/app/1966720/discussions/0/4034726898983980740)), так что для хоррора с монстрами это реальный риск. Своя проверка простая: каждый пир раз в N секунд пишет id, владельца, позицию и ключевые переменные объектов, а Python ищет расхождения.

## Звук: локальная музыка и голос, а проверка — простыми утилитами

Ваша политика (SFX из паков, ИИ только для голоса и музыки, $0, продажа игры) хорошо ложится на 2026 год. Для музыки лучший локальный вариант — **ACE-Step 1.5**: код MIT, работает меньше чем на 4 ГБ видеопамяти, есть REST API и сборка под Windows ([GitHub](https://github.com/ace-step/ACE-Step-1.5)). На 3080 идёт модель 2B turbo (до 6 ГБ). XL-модели требуют от 12 ГБ — не влезут. Агрегаторы пишут Apache-2.0, README — MIT; обе лицензии разрешают продажу.

Для голоса — **Chatterbox** (MIT, клонирование голоса, управление эмоцией) ([HF](https://huggingface.co/ResembleAI/chatterbox/blob/refs%2Fpr%2F48/README.md)) и **Kokoro** (Apache 2.0, быстрый, без клонирования, в списке языков есть русский — по словам продавца) ([tts.ai](https://tts.ai/blog/open-source-text-to-speech-guide-2026/?lang=ru)). Оба маленькие и должны идти на 10 ГБ. Качество русского ни для одной модели не измерено — нужен пробный прогон. F5-TTS (веса CC-BY-NC) и XTTS-v2 (некоммерческая лицензия, компания закрылась) продавать нельзя ([vantaige](https://vantaige.io/ai-tool/f5-tts); [promptquorum](https://www.promptquorum.com/power-local-llm/local-tts-voice-cloning-piper-coqui-xtts)).

Чтобы ИИ «слышал» звук, хватает простых утилит: ffmpeg (громкость, пики, тишина, спектрограмма в PNG), pyloudnorm, faster-whisper (переводит реплику обратно в текст и сравнивает со сценарием) и CLAP (оценка «похож ли файл на подпись "скрип двери"»). Большая «слушающая» модель Qwen3-Omni Captioner (Apache 2.0) хороша, но даже в 4 битах ей, видимо, нужно около 20 ГБ — на 3080 не влезет ([HF](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Instruct)). Gemini API понимает и шумы, но сжимает звук в моно 16 Кбит/с, так что подходит для вопроса «что это за звук», а не для оценки микса ([Google](https://ai.google.dev/gemini-api/docs/audio?lang=node)).

Бесплатный пак — **Sonniss GDC 2026**: около 7,5 ГБ от 17 поставщиков, без указания авторства ([Rekkerd](https://rekkerd.org/sonniss-releases-gdc-2026-game-audio-bundle/)). Лицензия запрещает обучение ИИ на этих файлах ([Zeli](https://zeli.app/en/story/49262841)). Разметка тегами для поиска — не обучение, но точный текст запрета мы не читали.

## Ассеты: сначала готовые бесплатные, генерация — потом и с оглядкой на лицензию

Для PSX-стиля почти вся «высокая» детализация ИИ-моделей выбрасывается: миллион треугольников и текстуры 4K всё равно ужмутся до сотен треугольников и 128–512 px. Поэтому самый дешёвый путь — сначала искать готовое через Blender MCP (`search_assets`: Poly Haven CC0, Poly Pizza) и только потом генерировать. Стиль держит ваш `psx_texture_tool.py`: через него должна проходить любая текстура из любого источника.

Видеокарта решает многое. TRELLIS.2 (MIT, лучшая открытая модель) требует 24 ГБ и проверена только на Linux ([GitHub](https://github.com/microsoft/TRELLIS.2)) — на 3080 не пойдёт, только аренда облачного GPU. У Hunyuan3D 2.1 форма занимает около 10 ГБ (впритык), текстура — около 21 ГБ (не влезет) ([GitHub](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)). Главная проблема — лицензия: она действует «по всему миру, **кроме ЕС, Великобритании и Южной Кореи**» ([HF LICENSE](https://huggingface.co/tencent/Hunyuan3D-2/blob/main/LICENSE)). Для игры в Steam с покупателями из ЕС это риск. Stable Fast 3D и SPAR3D лёгкие и бесплатны при доходе до $1 млн ([Stability](https://stability.ai/license)), но точный объём памяти не проверен. Бесплатный Meshy даёт 100 кредитов в месяц, то есть примерно 5 моделей, с лицензией CC BY 4.0 — продавать можно, но с указанием авторства ([Meshy](https://docs.meshy.ai/en/webapp/pricing)).

Две полезные функции Unity недоступны на вашей версии. Встроенная генерация LOD при импорте требует Unity 6.2+ ([Unity](https://docs.unity3d.com/6000.2/Documentation/Manual/lod/mesh-lod-generate-lods.html)). Новые Unity Generators требуют 6.3 и тратят платные кредиты ([Unity](https://docs.unity3d.com/Packages/com.unity.ai.generators@1.6/manual/index.html)). Упрощать сетку можно в Blender через MCP (Decimate, QuadriFlow).

## Вывод

Главное, что поменялось в картине: узкое место Snow — не нехватка умных инструментов, а то, что ИИ **не видит игру за пределами редактора** и **не обязан доказывать** свою работу. Оба пробела закрываются своим кодом за несколько вечеров: журнал в JSONL, dev-HTTP в игре и хуки-«шлагбаумы». После этого почти любая следующая задача — боты, сетевые прогоны, проверка звука, приёмка ассетов — превращается в «ИИ запустил, прочитал файлы, показал вам одну страницу итога». Готовые продукты из каждого раздела по сути продают эту же петлю, только за деньги и с чужими ограничениями.

Второй вывод — о лицензиях и видеокарте. Для проданной игры безопасны MIT/Apache-модели (ACE-Step, Chatterbox, Kokoro, TRELLIS.2) и модели Stability при доходе до $1 млн. Hunyuan3D проблемен из-за исключения ЕС. 10 ГБ видеопамяти хватает на звук и голос, но не на лучшие 3D-модели. Поэтому в 3D разумнее вложиться в поиск готовых CC0-ассетов и в PSX-обработку, чем в локальную генерацию.
